> [!WARNING]
> This is an internal development pre-release, not a release candidate. Bugs, visual differences, performance drops, freezes, and GPU crashes may still occur on real hardware.
**Included build: v0.78-11.** This release consolidates the internal v0.76 and v0.77 development lines and the current v0.78 work. The last public development release was [v0.75](https://github.com/WolffsRoom/DeltaruneVita/releases/tag/v0.75).

## Highlights

### v0.76 - Automatic renderer and GPU fallbacks

* Added **Automatic** as the default renderer policy. Chapter 3 selects the proven Legacy-GL backend because Round 2 repeatedly GPU-crashed under Modern-GL; the other chapters retain Modern-GL and its wider shader support.
* Kept Chapter 3 shaders available outside the affected path while adding room-specific RGBA uploads, shader fallbacks, resident pages, frame-boundary eviction, and transition barriers for the gameshow/board rooms.
* Hardened Modern-GL texture, surface, uniform, and retired-resource lifetime management across room changes and Room Navigator jumps.
* Preserved the v0.75 BC3/DXT5 work, Garden/Flowey fixes, border cleanup, and Chapter 5 video support while continuing to tune memory limits from hardware logs.

### v0.77 - Experimental-GL, chapter fixes, and loading

#### Renderer and settings

* Added **Experimental-GL**, an opt-in mode that keeps Legacy-GL's stable texture, surface, batching, and lifetime paths while enabling an audited programmable shader bridge. Unsupported or failed effects fall back to the regular textured path.
* Expanded the Game Settings descriptions, renderer diagnostics, FPS policies, texture profiles, screen filters, and restart handling.
* Improved 30 FPS pacing so a late VBlank does not add an extra 16.7 ms delay to the software deadline.

#### Chapters 2–5

* Chapter 2 Mansion transitions now reserve room for large surfaces and trim their texture working set before memory-heavy doors.
* Chapter 3 received centered minigame composition, reduced redundant monitor copies, corrected quiz palettes, rhythm input/audio-clock fixes, safer Round 2 loading, faster battle entry, finale border rules, visible music prompts and Knight attacks, and shorter checkpoint retries after defeat.
* Chapter 4 fountain/black-border rules and audited shader coverage were extended through the Experimental bridge.
* Chapter 5 Town shadows were restored in Experimental-GL; Castle Town, cliffs, Garden battles, Flowey video, Room Navigator transitions, and the final battle received targeted memory and workload policies.
* The final Flowey tower keeps all structural layers visible and reuses its expensive composition at a reduced update cadence. Garden petals, border fades, duplicated TP presentation, and missing scene textures received dedicated fixes.

#### Shared presentation and stability

* Battle dialogue glyphs now sample atlas texel centers, restoring the bottom pixel line in Chapters 1–5.
* Chapter loading appears before trophy setup and `data.win` parsing instead of leaving a long black screen.
* Room changes synchronize and collect outgoing GPU resources at safe boundaries; recently reloaded atlases receive a short stability window to reduce eviction/reload loops.
* Returning to the chapter selector, entering borderless rooms, and scripted border changes now fade to black without leaking the previous room's frame.

### v0.78 - startup, unified package, and Native GXM backend

#### Startup and LiveArea

* Added the new 18-second opening video and converted it to the Vita-compatible contract: H.264/AVC Constrained Baseline level 3.1, 960×544 at 30 FPS, `yuv420p`, and AAC stereo at 48 kHz. The last frame hold and fade-out remain active.
* VitaGrafix/VGi no longer disables video playback. The safety fallback is limited to USB audio/video capture plugins that directly compete with the hardware video path.
* Added early native validation for required game data and `libshacccg.suprx`, with readable diagnostics instead of silent startup failure.
* Updated the LiveArea icon, background, and startup image from the new asset set; the old `pic0` overlay is no longer included.
* The Chapter 0 footer and package version now report **v0.78**.

#### Loading and frame pacing (v0.78-8)

* Chapter 0 `data.win` parsing now starts while the opening video plays. If the background task fails, the existing synchronous load is still used.
* Lazy room payloads can be prepared by a single bounded background worker before a room change. The previous room stays active until the required payload is ready, so Room End/Start order is unchanged.
* Lazy texture reads use a separate file handle and a CPU-only staging step. Texture creation and GPU upload still happen on the main thread to avoid new GPU crash risks.
* The 30/40 FPS limiter now uses absolute deadlines with an adaptive wait margin. A late frame restarts the cadence instead of being followed by a short catch-up frame.
* The worker uses the fourth CPU core when CapUnlocker is available and falls back to the normal core otherwise. Total staging memory is limited to 8 MiB.
* New `STARTUP_PRELOAD`, `VITA_ROOM_PREFETCH`, and `IO_PROFILE` log entries make loading and wait times comparable on hardware.

#### Unified VitaGL + Native GXM package (v0.78-9 to v0.78-11)

* The VPK now contains a small launcher and two independent executables: `vitagl.bin` and `gxm.bin`. The graphics backend can be changed from Game Settings; the opening video still plays before the selected backend starts.
* Fixed the native RGBA4444 format that turned Chapters 1–5 pink on the GXM backend.
* GXM and VitaGL now share the same saves in `ux0:data/deltarune_saves/`.
* The language selected in Game Settings is also applied to the `data.win` and assets loaded by the GXM backend.
* Added protection against self-intersecting quads, a possible source of the black polygon artifacts seen during transitions.
* Already adapted GXP shaders are kept, with the safe fallback when an effect has no native implementation yet.

## Native GXM backend

v0.78 started a separate **Native GXM** renderer project intended to eventually replace VitaGL. It uses `sceGxm` directly with embedded GXP shaders, and progressed from direct GXM presentation to the real Butterscotch parser, VM, Runner, texture pages, bitmap fonts, surfaces, audio, chapter switching, shader adaptations, and real Chapter 0/3/5 scenes.

Starting with v0.78-9, this backend ships inside the same VPK as an **optional** choice in Game Settings.

> [!IMPORTANT]
> Native GXM remains **experimental**. It does not yet provide full visual, shader, video, performance, or chapter parity. **VitaGL** (Automatic, Legacy-GL, Modern-GL, and Experimental-GL) remains the default and recommended backend.

## Installation

1. Install **`Deltarune-v0.78.Internal-Build-Test.vpk`** with VitaShell. The internal build marker in `butterscotch-probe.log` should report **v0.78-11**.
2. Keep the prepared game data at `ux0:data/deltarune/deltarunevita/`.
3. If the two Chapter 5 videos are not already installed, use the existing **`Deltarune-v0.75-Chapter5-Videos.zip`** from the [v0.75 pre-release](https://github.com/WolffsRoom/DeltaruneVita/releases/tag/v0.75) and copy its `chapter5` directory into the data directory.
4. Install `libshacccg.suprx` at `ur0:data/libshacccg.suprx`. The game now reports this dependency clearly when it is absent.
5. Use `SHA256SUMS.txt` to verify the download.
